# 项目设计意图

## 1. 项目定位

本项目是一个以 Terminal / Shell 为核心视觉语言的个人主页，用于集中展示个人介绍、技术方向、研究兴趣、项目经历、技能与联系方式。

Terminal 并不是项目本身的目的，而是一种能够体现技术背景、增强辨识度并统一整体体验的交互与视觉形式。

网站首先是一个个人信息展示页面，其次才是一个具有终端交互特色的实验性界面。

## 2. 项目目标

本项目希望实现以下目标：

- 建立具有明确辨识度的个人主页，而不是使用通用 Portfolio 模板。
- 让访问者能够快速了解个人背景、研究方向和代表性项目。
- 通过 Terminal 风格自然体现计算机、软件工程和人工智能相关技术背景。
- 在个性化交互与实际可用性之间保持平衡。
- 保持整体设计简洁、克制、统一。
- 保持网站轻量、快速，并具有良好的可维护性和扩展性。

## 3. 目标访问者

主要访问者包括：

- 希望了解个人背景、项目和研究方向的人。
- 软件工程、人工智能、LLM Agent 等相关领域的同行。
- 教师、研究人员以及潜在的合作伙伴。
- 对个人项目或技术经历感兴趣的开发者。
- 并不熟悉 Shell，但希望快速浏览个人信息的普通访问者。

网站不应假设访问者具有命令行使用经验。

## 4. 核心体验

### 第一印象

访问者进入网站后，应立即感受到明确的 Terminal 风格和技术氛围。

整体体验应简洁、克制、清晰，而不是依赖大量装饰、复杂动画或夸张的“黑客”效果制造技术感。

Terminal 风格应成为网站自然的一部分，而不是覆盖内容本身的视觉噱头。

### 使用体验

网站应提供一定的探索感和交互感。

熟悉 Terminal 的用户可以通过类似命令行的方式进行探索，但这种交互不应成为使用网站的必要条件。

页面的基本浏览、滚动、链接访问、文本选择和复制等行为应符合正常网页的使用习惯。

任何特殊交互都不应明显增加学习成本或降低访问效率。

### 信息获取

访问者应能够较快回答以下问题：

- 这个人是谁？
- 主要关注哪些技术或研究方向？
- 做过哪些值得关注的项目？
- 当前正在做什么？
- 如何进一步了解这些工作？
- 如何联系本人？

页面设计应帮助用户建立这些信息之间的层次关系，而不是单纯展示大量独立信息。

## 5. 核心设计原则

### Terminal 是设计语言，而不是真实 Shell

Terminal 是本项目的视觉和交互隐喻。

项目不追求完整模拟 Linux、Unix 或其他真实 Shell 环境，也不应为了提高“真实感”而引入与个人主页目标无关的复杂功能。

所有 Terminal 行为都应服务于个人信息展示和页面体验。

### 内容优先于形式

个人信息、项目、研究经历和其他实际内容始终是网站的核心。

视觉效果、动画和 Terminal 交互不能明显降低内容的可发现性、可读性和访问效率。

当视觉形式与信息获取发生冲突时，应优先保证内容展示。

### 简洁优先

相比复杂和炫目的界面，本项目更重视一致、清晰和克制。

新增功能和视觉元素应有明确作用。

能够通过简单设计完成的内容，不应通过不必要的复杂结构、动画或依赖实现。

### 交互是增强，而不是门槛

Terminal 交互用于增强体验，而不是限制访问方式。

熟悉命令行的用户可以获得更多探索感，但不了解 Terminal 的用户同样应该能够理解和访问网站的主要内容。

核心信息不应只存在于某个不易发现的命令、隐藏入口或复杂交互流程中。

### 技术感来自真实内容

网站的技术感应主要来自真实的项目、研究内容、技术经历以及一致的 Terminal 设计语言。

不依赖大量装饰性的“黑客”元素、随机代码、无意义系统日志或夸张动画塑造技术形象。

形式应强化真实内容，而不是代替真实内容。

## 6. 非目标

本项目不以以下内容为目标：

- 模拟完整的操作系统或 Shell。
- 提供真实命令执行能力。
- 实现完整的虚拟文件系统。
- 成为一个复杂的 Web 应用平台。
- 使用大量 Terminal 特效本身作为主要展示内容。
- 为追求视觉效果牺牲移动端体验、可访问性或基本网页行为。
- 将所有内容强制隐藏在命令输入之后。
- 为简单需求引入不必要的复杂技术栈或大型依赖。
- 为增加功能数量而加入与个人主页定位无关的功能。
- 追求完全拟真的 Terminal，而忽略个人主页作为信息载体的主要作用。

## 7. 长期不变量

无论未来如何调整页面结构、技术栈或具体实现，以下原则应尽量保持不变：

- 网站首先是个人主页，而不是 Terminal 模拟器。
- Terminal 始终是主要视觉和交互语言之一。
- 个人背景、研究方向和代表性项目必须容易访问。
- Terminal 交互不能成为获取核心内容的必要条件。
- 内容的重要性始终高于装饰和动画。
- 整体视觉应保持简洁、克制和统一。
- 网站应保持较轻的运行成本和良好的加载体验。
- 桌面端与移动端均应具有可接受的使用体验。
- 技术感应建立在真实内容和真实经历之上。
- 新功能不应破坏已经建立的整体设计语言。
