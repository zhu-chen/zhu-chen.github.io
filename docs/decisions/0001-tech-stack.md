技术选型决策：Astro + TypeScript + xterm.js

决策日期：2026-09-25。状态：已确认。决策来源：项目所有者明确选择 Astro + TypeScript + xterm.js。

**项目采用 Astro + TypeScript + xterm.js 作为核心技术栈。** 后续设计和实现以此为依据，先前调研中的候选排序与默认推荐保留为历史参考。

| 技术 | 职责 |
| --- | --- |
| Astro | 组织页面、布局和内容，构建静态站点 |
| TypeScript | 实现内容类型、命令逻辑、导航和交互状态 |
| xterm.js | 提供浏览器端终端显示与输入事件接入，配合 TypeScript 实现网站命令交互 |

这一组合使用 Astro 的内容组织与静态生成能力，并由 xterm.js 承担终端呈现。终端组件在浏览器端初始化，命令与内容适配逻辑使用 TypeScript 维护。部署目标沿用项目既定的 GitHub Pages。

选型继续遵循 [项目设计意图](../intend.md)：

- Terminal 交互服务于个人与学术信息展示，核心内容容易发现。
- 不熟悉 Shell 的访客也能访问主要内容。
- 命令仅触发预定义的网站操作，不提供真实 Shell 执行能力。
- 保持正常链接、滚动、选择与复制行为，并验证桌面端、移动端和可访问性。

**本次确认的是核心技术栈。** 页面布局、具体命令、终端与普通 HTML 内容的协作方式、内容格式、依赖版本及 xterm.js 插件，在后续 Spec 和 Design 中确定。本决策不将先前调研中的所有实现建议自动升级为已确认需求。
